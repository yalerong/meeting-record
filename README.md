# 会议录音与纪要

这是一个仅在本机运行的 Windows 小程序：

1. **同时用两路麦克风通道录音**，任何一路挂掉或被驱动压成静音，另一路还在。
2. 结束后使用 faster-whisper `large-v3-turbo` 模型转写中文。
3. 用 sherpa-onnx 做说话人分离，逐字稿标上「说话人1/2/3」。
4. 转写模型释放内存后，使用 Ollama `qwen2.5:7b` 生成带时间戳证据的会议摘要、决定、行动项和待确认问题。
5. Ollama 失败时自动生成基础纪要；任何处理失败都不会删除原始录音。

## 使用

双击 `start.bat`。程序一打开就会持续试音：**先对着电脑说一句话，确认“输入电平”条明显跳动、下面提示变成“麦克风工作正常”**，再输入会议名称并点击“开始录音”。会议结束后点击“结束并生成纪要”。

会后处理分三个阶段，界面上都有进度：

- 阶段 1 转写：百分比、已处理到录音的第几分钟、已识别多少句、预计还要多久。**逐字稿边转写边写盘**，中途关程序也不会丢已经转好的部分。想中断就点“停止处理”。
- 阶段 2 说话人分离（可关掉）：约占录音时长的 1/10。
- 阶段 3 生成纪要：显示第几步/共几步。

程序崩溃、断电或当时没处理完的录音，用 **“处理已有录音…”** 选中那个 `原始录音.wav` 就能重新走一遍，不用重录。

结果保存在 `meetings/<日期时间-会议名称>/`：

- `原始录音.wav` / `备份录音.wav`（两路各存一份）
- `逐字稿.txt`
- `会议纪要.md`
- `录音日志.txt`（两路各自的设备、实际录到的时长、最大音量、自动重连次数）

## 拿到音频是第一位的

录音端做了这些事，目标是“无论如何都要留下能听的音频”：

- **双路冗余**：主路用你选的设备，备份路自动挑同一支麦克风的另一条通路（MME ↔ WASAPI）或另一个物理设备，各写各的文件。结束时如果主路是静音而备份路有声音，**自动改用备份录音**去转写。
- **实时电平条**：录到的是静音会立刻显示，连续 15 秒没声音就变红报警并响铃。
- **计时器按实际写入的音频算**，不是墙上时间。流断了计时器就停，一眼看得出来。
- **采集看门狗**：麦克风超过 2 秒不送数据就自动关闭并重开音频流，续写同一个 WAV，重连记录进 `录音日志.txt`。
- **30 秒预录**：点“开始录音”时，会把点击之前最近 30 秒的试音一起写进文件，点晚了也不丢开头。
- **每 5 秒落盘并修补 WAV 文件头**：程序被强杀、断电、睡眠，最多只丢最后 5 秒，文件仍可播放。
- 录音期间阻止系统睡眠和息屏，并每 30 秒重申一次。
- 开始前检查磁盘剩余空间（两路合计约 230MB/小时）。

## 转写与纪要的质量保护

- **录音偏小会自动放大后再转写**（最多 20 倍，原始 WAV 不改），远场会议不至于被识别成空白。
- **过滤 Whisper 的经典中文幻觉**（“请不吝点赞订阅转发打赏”“字幕由…提供”之类）和连续复读，过滤条数写在逐字稿开头。
- `condition_on_previous_text=False`，避免长录音陷入复读循环。
- 说话人标签只用来区分“谁说的”，提示词明确禁止模型据此臆测真实姓名和职务。
- 纪要阶段先检查 Ollama 是否在跑、模型是否存在；不可用时会明确告诉你“这份是简易兜底版”，不再默默降级。

## 会前建议

- 把电脑放在会议桌尽量靠中央的位置，麦克风孔不要被文件或衣物遮挡。
- 接通电源，不要合上笔记本屏幕。
- 开始前一定要看一眼电平条：内置麦克风阵列带噪声抑制，说话人离得远时可能被压成纯静音。
- 会议期间不要关闭程序。即使转写稍后失败，WAV 录音仍会保留。
- 处理阶段全在本机跑，风扇高速运转属于正常现象。

## 录不到声音时

1. 看 `录音日志.txt` 里两路各自的“最大音量峰值”。低于 60/32768 说明进来的就是静音。
2. Windows 设置 → 系统 → 声音 → 输入：确认麦克风没有静音、音量不是 0。
3. 在程序里换一个麦克风设备（下拉框）再试音，MME 和 WASAPI 两个条目都可以试。
4. 说话人离电脑 1 米以内，或改用外接麦克风/会议全向麦。

## 安装

需要 Windows + Python 3.10 以上。

```
pip install -r requirements.txt
python download_models.py     # 可选：下载说话人分离模型（约 35MB）
```

会议纪要由本机的 [Ollama](https://ollama.com) 生成，需要先拉模型：

```
ollama pull qwen2.5:7b        # 最终合并用
ollama pull qwen2.5:3b        # 可选：长会议的分段摘要用它，省一半时间
```

转写模型 `large-v3-turbo` 首次运行时自动下载（约 1.6GB）。

## 速度参考

在一台无独显的笔记本（纯 CPU）上实测：

| 阶段 | 速度 |
|---|---|
| 转写 large-v3-turbo int8 | 约 2 倍实时 |
| 说话人分离 | 约 12 倍实时 |
| 纪要生成 qwen2.5:7b | 约 1.5 token/s |

也就是说 2 小时的会议，全部处理完大约要 2–3 小时，其中绝大部分花在生成纪要上。录音本身不受影响。

## 隐私

音频、逐字稿、纪要全部只留在本机，程序不向任何外部服务发送数据（Ollama 和转写都是 localhost）。

`meetings/` 已经写进 `.gitignore`，`*.wav` 也一并挡掉。**如果你 fork 或复制这个项目，发布前请再确认一遍 `meetings/` 没有被提交。**
